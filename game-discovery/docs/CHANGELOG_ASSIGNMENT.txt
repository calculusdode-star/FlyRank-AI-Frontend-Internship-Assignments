CHANGE 004 — Correct login and registration redirects

Date:
2026-09-17

Requirement:
Make login and registration redirect reliably after Firebase authentication
and preserve the authenticated state on Home.

Files:
- `src/pages/Login/LoginView.jsx`
- `src/pages/Register/RegisterView.jsx`

Previous state code:

```jsx
try {
  await loginUser(email.trim(), password)
} catch (error) {
  setAuthenticationError(getLoginErrorMessage(error))
}
```

```jsx
try {
  await registerUser(email.trim(), password)
} catch (error) {
  setAuthenticationError(getRegistrationErrorMessage(error))
}
```

Previous state also navigated from the submit handlers before the
`AuthContext` update was necessarily reflected in React.

Current state code:

```jsx
useEffect(() => {
  if (!authLoading && user) {
    navigate('/', { replace: true })
  }
}, [authLoading, navigate, user])
```

```jsx
try {
  await loginUser(email.trim(), password)
  navigate('/', { replace: true })
} catch (error) {
  setAuthenticationError(getLoginErrorMessage(error))
}
```

The registration handler uses the same pattern with `registerUser(...)`.

Comparison/code change:
Added `user` and `authLoading` from `AuthContext`, retained the auth-state
effect as a synchronization fallback, and added immediate navigation after
successful login or registration. Failed authentication skips navigation and
remains on the relevant form.

Result:
Firebase authentication completes, the user is navigated to `/`, and Home and
Header can receive the authenticated state from `AuthContext`.

Verification:
Tests: 56/56 passed. Lint passed. Build passed. Live Firebase flows were not
performed.
Result: PARTIAL.

Remaining issues:
Live login, registration, and failed-authentication flows still require
verification with a Firebase test account.
